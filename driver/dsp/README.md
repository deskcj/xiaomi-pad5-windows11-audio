# MiSound support source

`NabuAcdbGetGlobalPropertyView` now exposes an unchanged GPROPLUT/DATAPOOL
resource view, including `0x132AC`, with complete table/pool bounds and duplicate
checks. It preserves opaque bytes and rejects non-global headers. All 31
properties from Windows/HyperOS files match an independent decoder; 12 boundary
and malformed cases and 33 real NOACCESS cases pass. Ghidra confirms selector 3
of `0x140061208` calls global loader `0x14005ea58`; `0x140052f38` copies the
resource for registration rather than interpreting MiSound algorithms. These
are file preparation and static code checks, with no live resource load or DSP
command. [Current evidence](../../docs/results/audio-dolby-runtime-acdb-2026-11-26.json)

`MiSoundAudioConfig.c/.h` reproduce the captured `MiSound_setConfig` validation and preserve all 112 configuration bytes. Rates, masks and format bytes must match; output access is 0 or 2. The original channel count matches the mask popcount. All 246 executions of the original Android function match, including 150 rejections, and 16 native boundary/null/overlap cases pass. Opaque Android pointers are copied as data and never dereferenced on Windows. Accepted format IDs are not Windows format negotiation or evidence of hardware PCM24. [Configuration evidence](../../docs/results/audio-config-capx-stereo-2026-11-25.json)

`MiSoundProtocol.c/.h` encode the original Android control commands. `MiSoundResource.c/.h` validate the captured SPKD/SPMD/NUMM container and all named profile/module records before visiting their raw selectors and binary32 value bits. `MiSoundSpeakerFilters.c/.h` then read the SPMD/MMFD tables without changing their coefficients or scales. Damaged profile tails now reject the resource even when its filter section is intact.

`MiSoundSpeakerPlan.c/.h` reproduce the original `MiSoundDSP_SetSPKParam` sequence for 4- and 8-byte controls. This includes both AppType IDs, active/persistent routes, the five caller-supplied factory rates, mode exceptions and exact unpadded Base64. The returned plan contains 2, 4, 10 or 12 commands. All 864 comparisons against execution of the original Android ARM64 code passed, plus 53 native guard-page and 13 invalid-input cases. [Speaker-plan evidence](../../docs/results/audio-misound-speaker-plan-2026-11-25.json)

The original `DSPVarFS` table contains 44100/48000/88200/96000/192000. These are control/calibration routing values, not proof of Windows playback at those rates. The helper preserves the original final route, including its rate and persist flag; it does not choose values, apply controls or enable MiSound. Unsupported requests leave its output untouched even though the Android wrapper may update its own internal route without dispatching a command.

The two captured resources contain seven profiles and nineteen modules each: 247 stereo and 255 four-channel parameter records. All 502 records were compared exactly. Thirteen malformed cases, ten filter-only regression comparisons and 30,770 native bounds/mutation cases passed; the ten original filter tables and fourteen rejection cases still pass. [Evidence](../../docs/results/audio-misound-resource-2026-11-25.json)

Original HyperOS instructions also select the existing 192000-Hz table for a 176400-Hz request. The reader now preserves that selection, reporting the factory table rate without resampling. Both alias cases match every original table bit; fourteen nearby/invalid-rate cases still reject without changing the output. This does not establish hardware playback at those rates.

`QualcommAcdbRoute.c/.h` now resolve the captured device/application/rate through the uncompressed ACDB DPROPLUT, AGIILUT0 and version-2 GPROPLUT `0x132ac` records. Bounds, ambiguous selections and exact module qualifier words are checked before returning a file-route match. The qualifier is preserved as an opaque topology field; it is not a parameter instance or a physical speaker index. Unrecognized graph versions are rejected. This scans referenced routing/calibration structures, not every opaque ACDB chunk or calibration value.

`QualcommPpParameter.c/.h` pack a 16-byte Windows `param_hdr_v3` followed by the exact payload. The instance must be supplied from the captured calibration/control state. Oversized payloads, insufficient buffers and instances outside 16 bits reject without changing the output. Payload/output overlap is supported. All 91 captured factory MiSound/Dolby payloads match execution of the original Windows QCADCM handler; allocation, COPP lookup, CRT memory operations and APR replies were mocked. Passing these checks does not establish a live COPP, module resource loading or DSP acknowledgement. [Route and parameter evidence](../../docs/results/audio-acdb-pp-2026-11-25.json)

The current configured Windows Device 73 music graphs select `0x10000009` with seven stock modules, neither MiSound nor Dolby. The Android music graph selects `0x1000a100` with those two effects. No device IDs, topologies or parameters are automatically substituted. Topology registration (`0x12923`) and online ADM parameter setting (`0x1035d`) are distinct operations. The next integration step must confirm a compatible live graph and COPP before any dispatch. Software Dolby APO binding is a separate Windows graph check; missing DSP modules do not diagnose that binding.

`QualcommCoppSelector.c/.h` reproduce original QCADCM stream-mask selection without reading its context tables. A one-hot low byte is required; paired contexts need a one-hot second byte, and bit 18 retains its original precedence. The stricter ADM entry check rejects the upper bits that the original online wrapper would discard. These indices are driver context slots, not Android ACDB IDs or speaker positions. All 3,146 original ARM64 comparisons pass, including invalid selectors, plus 27 real NOACCESS cases.

`QualcommHostCalibration.c/.h` construct the original common-calibration GET header, payload capacity and three padding bytes. IDs must be explicitly supplied; the helper rejects zero IDs, instance truncation and length overflow before writing. All 95 original getter comparisons (91 HyperOS and four Windows records) and 21 native NOACCESS cases pass. The original ACDB lookup/allocation/copies were mocked in those comparisons.

The new C header also passed a real read through the running OEM ADCM device: the stock PBE-enable buffer matched the installed Windows ACDB. The original MiSound-enable query returned Win32 31 with an unchanged buffer. This is host-cache access through `0xadae2105` / ACDB `0x13263`, not a live DSP parameter GET or ACK. The OEM completes with zero API byte count even after writing the buffer; the bounded header/capacity, marker change and exact file value are retained in the evidence. No SET was sent. [Native selector and host-cache evidence](../../docs/results/audio-adcm-host-selector-2026-11-25.json)

Later PP comparisons execute the original COPP lookup against emulated context contents instead of replacing that lookup. All 91 factory payloads still match. Live COPP identity, resource opening, DSP processing and physical L/R remain unverified.

`QualcommPpReadback.c/.h` add the original 28-byte Windows ADM GET body and a bounded out-of-band v3 response view. Mapping address, handle and capacity must belong to a verified live transport; the OEM capacity includes the 16-byte response header. The validator requires exact module/instance/parameter and returned length, rejects reserved bits and never approves coefficient values. All 112 original GET comparisons (91 factory blocks), 76 native NOACCESS cases and 13 invalid-response cases pass. The original transport/reply and active mapping were emulated; no live GET or DSP ACK was observed. [Readback evidence](../../docs/results/audio-adm-readback-2026-11-25.json) · [Qualcomm reference structures](https://android.googlesource.com/kernel/msm-extra/+/7d02ebed32f03421d272eae1831dda37f24f2147/include/dsp/apr_audio-v2.h)

`NabuQcomValidateAdmGetReply` validates a standard 20-byte APR response before accessing parameter data: both endpoints, token, V6 response opcode, DSP status and exact message length. In-band and mapped out-of-band buffers are explicit. A basic GET response with status zero cannot substitute for parameter data; error/stale/misrouted replies leave the output view untouched. The original OEM response allocation is 144 bytes; extended headers are intentionally unsupported because its receiver normalizes payload to offset 20. The helper does not authenticate a fixture or approve calibration values. Its key/mapping must belong to a verified live transaction. The current library passed 112 original mapped GET readbacks, 100 constructed in-band packets, 21 rejected replies, 73 new and 76 retained memory cases. Original queue/key ownership and response status were modeled; no live DSP reply was observed. [Reply/source evidence](../../docs/results/audio-apr-stereo-source-2026-11-25.json) · [Xiaomi APR definitions](https://github.com/MiCode/vendor_qcom_opensource_audio-kernel/blob/d41f8e1a6827294af6a61adbe18544518e750166/include/ipc/apr.h)

This is a user-mode support library. Structural acceptance is not approval of calibration values. It preserves raw OAL/dynamics records without implementing their algorithms, units or DSP dispatch. It does not process audio or enable system MiSound. The CS35L41 driver and current public ZIP do not apply these tables.

The input must remain unchanged throughout a scan. Complete structural validation precedes callbacks; cancellation can still occur after earlier callbacks, leaving the optional summary untouched. Collect records before attempting a DSP transaction. Profile/module order and both selectors are preserved; DSP indices do not establish physical left/right speaker positions.

From an ARM64 EWDK environment, run `powershell.exe -File .\Build-MiSoundSupport.ps1 -OutputDirectory <new-folder>`. It builds all ten components into `NabuMiSoundSupport.lib` and records the source hashes. No installation or device access occurs.
